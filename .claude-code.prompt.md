# Start

This repo will contain an emacs extension. We will start by initializing the project and a CLAUDE.md

The vision here is that while I'm working, I can have a dedicated buffer open and showing a "heads up display" for the current code. This will feature several analyses of the current code context

For the file open in the current code window:

- what is its current git status.
- what other files historically change at the same time this file changes (similar to adam tornhill's code-maat and code-as a crime scene)
- Who are the people who have touched this file, accompanied by the number of times they've touched it, sorted
- An llm summary in <3 sentences of the purpose of this file (generated by claude, cached hourly)
- An llm summary in <5 sentences of the history of this file (generated by claude, cached daily)

# Architecture
I think we're working in the right direction but I want to make some architectural tweaks.

Firstly, I think our `*gim-code-hud*` buffer should be an org buffer with headings for each of the sections

Second, I want caching in sqlite with ids like `purpose:<file-path>` and a `value` and `valid-until` field

Third, all of our code-hud values should be cached. Finally, all updating of our hud buffer should proceed through a central point. Specifically I'd like to maintain a stack of "code hud update requests" where a request is a heading, a string value, and the time at which that value was retrieved. While the code hud buffer is visible, it should pop items from that list one by one and write them into the buffer.

The minor mode should maintain a list of the next time each code hud heading for each file we've used it on needs to be updated. These timestamps would update whenever we get new values which should only happen while the code hud is active and on that file. We check whether its time to update any of these every 5 seconds. This is what pushes onto the code hud update requests stack

In other words, there are only *two* timers running at a time. One which flushes the update requests to the code hud buffer and another which checks whether any values for the currently active buffer need updating.

There should exist interactive functions for toggling each of these timers on/off (return 't or nil depending on the newly toggled state) and toggling it on should force it to run immediately.

Does that make sense? Any questions? Any impreovements? Please ask questions to clarify and drive out design when its not clear
